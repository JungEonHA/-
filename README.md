# 근무시간 관리 (Notion Embed)

실시간 출퇴근 타이머 · 휴가 관리 · 주간/월간 집계 · Notion 자동 기록.
Notion 페이지에 그대로 Embed 할 수 있는 개인용 근무시간 관리 웹앱.

```
출근 → 자리 비움 → 복귀 → 퇴근 → Notion 근무시간 DB 에 자동 기록
```

---

## 먼저 타이머만 쓰고, Notion 은 나중에

**Notion 연결 없이도 앱 전체가 정상 동작한다.** 타이머·자리비움·휴가·주간/월간 집계는
전부 로컬에서 돌아가며, Notion 관련 설정을 하나도 건드리지 않아도 된다.

- 퇴근할 때마다 그 날짜가 **보관함에 쌓인다**. 나중에 Notion 을 연결하면
  그동안 쌓인 날짜가 **한 번에 기록**된다 — 미리 연결해 둘 필요가 없다.
- 백엔드가 없다고 확인되면 자동 재확인 간격을 늘려서, 실패하는 요청이
  계속 나가지 않는다.
- Notion 미연결 상태에서는 경고 배지를 띄우지 않는다. 문제가 아니라 정상 상태다.

로컬 PC 에서 바로 쓰려면:

```bash
git clone https://github.com/JungEonHA/-.git worktime && cd worktime
npm ci
npm run dev        # http://127.0.0.1:5173
```

기록은 브라우저에 저장되므로 **같은 브라우저에서 같은 주소로** 접속해야 이어진다.
주소를 옮길 때는 설정 → **JSON 내보내기 / 가져오기** 를 쓴다.

## 설계 요점

### 1. 시간 계산 — 카운터를 쓰지 않는다

`setInterval` 로 숫자를 더해 나가는 방식은 탭이 백그라운드로 내려가거나(브라우저 throttling),
컴퓨터가 절전에 들어가거나, 새로고침하는 순간 값이 어긋난다.

이 앱은 **출근/자리비움/복귀/퇴근의 절대 시각(epoch ms)만 append-only 로 저장**하고,
화면을 그릴 때마다 그 타임스탬프로부터 경과시간을 다시 계산한다.
`setInterval` 은 오직 "다시 그릴 때가 됐다"고 알리는 용도이며 계산에 관여하지 않는다.

덕분에

- 백그라운드 탭에서 타이머가 1초에 한 번도 못 돌아도 값이 정확하다
- 절전에서 깨어나면 흐른 시간이 그대로 반영된다 (`visibilitychange` / `focus` 에서 즉시 재계산)
- 새로고침해도 이벤트만 복원하면 상태와 경과시간이 그대로다

시간대는 **Asia/Seoul 고정 오프셋(UTC+09:00)** 으로 계산한다. 한국은 1988년 이후 서머타임이
없으므로, 런타임 tz 데이터에 의존하는 대신 결정적인 고정 오프셋 산술을 쓴다.

### 2. 실제 근무 / 휴가 대체 / 인정 근무의 분리

| 값 | 의미 |
| --- | --- |
| 실제 근무시간 | 자리 비움을 제외하고 실제로 일한 시간 |
| 휴가 대체시간 | 해당 일자에 사용한 휴가 |
| 인정 근무시간 | 실제 근무시간 + 휴가 대체시간 |

### 3. 휴가 — 잔여를 저장하지 않는다

매월 8시간(설정 가능) 지급, 미사용분은 다음 달로 이월.

잔여량을 어딘가에 저장해 두고 더하고 빼면 언젠가 어긋난다. 대신 **항상
`지급 누계 − 사용 누계` 로 다시 계산**한다. 사용 내역은 근무 기록과 같은 곳
(`DayLog.vacationMs`)에 저장되므로 두 데이터가 따로 놀 수 없다.

```
1월 지급 8h, 1월 사용 3h  →  잔여 5h
2월 지급 8h              →  2월 사용 가능 13h
```

### 4. 데이터 안정성 — 로컬이 1차 진실

Notion 동기화는 로컬 기록 위에 얹힌 부가 작업이다.

- 동기화가 실패해도 로컬 기록은 **절대 지워지거나 되돌려지지 않는다**
- 실패한 항목은 outbox 에 남아 지수 백오프로 자동 재시도되고, 수동 재시도도 가능하다
- outbox 는 "어떤 날짜가 dirty 한가"만 담는다. 전송 페이로드는 보내기 직전에 최신
  로그로부터 다시 만들기 때문에, 재시도가 낡은 값을 덮어쓸 수 없다
- localStorage 를 쓸 수 없는 환경(iframe 차단/시크릿 모드)을 감지해 경고를 띄우고
  메모리 저장소로 대체한다
- 저장 슬롯이 손상되면 백업 슬롯에서 복구한다. JSON 내보내기/가져오기도 지원한다

### 5. Notion Property 를 하드코딩하지 않는다

앱은 실제 DB 의 Property 이름을 **추측하지 않는다.**

1. 서버가 런타임에 `GET /v1/databases/{id}` 로 실제 스키마를 읽는다
2. 이름·타입이 호환되는 후보를 **제안**한다 (확정은 사용자가 설정 화면에서 한다)
3. 매핑되지 않았거나 타입이 안 맞는 필드는 조용히 **건너뛴다** — 억지로 쓰지 않는다
4. Property 추가는 명시적으로 버튼을 눌렀을 때만, **추가만** 한다

기존 데이터 보호:

- 페이지 갱신은 `PATCH`(부분 병합)이므로 매핑된 Property 외에는 건드리지 않는다
- 삭제/아카이브를 하는 코드 경로가 **존재하지 않는다**
- 같은 날짜의 행이 여러 개면 가장 오래된 것만 갱신하고 나머지는 그대로 둔 채 경고한다

### 6. 중복 기록 방지 — 그리고 "남의 행은 건드리지 않는다"

상태가 바뀔 때마다(출근·자리 비움·복귀·퇴근·업무 복귀·휴가 변경) Notion 에 보내지만
행이 늘어나면 안 되므로:

1. 앱이 기억하는 `pageId` 가 있으면 바로 `PATCH` (없어졌으면 아래로 폴백)
2. 없으면 **날짜 + 직원** Property 로 조회
3. 조회 결과 중 **앱이 만든 행**(제목이 `YYYY-MM-DD <직원> 근무기록`)만 갱신 대상
4. 앱이 만든 행이 없으면 새로 만든다

3번이 핵심이다. 예전에는 날짜만 맞으면 가장 오래된 행을 갱신했는데, 사용자가 손으로
적어 둔 행("반차", "근무" 같은)이 그 조건에 걸려 제목과 구분이 통째로 덮어써지는
사고가 있었다. 이제 앱은 자기가 만든 행만 갱신하고, 남의 행을 발견하면 손대지 않은 채
설정 화면에 그 사실을 알린다.

### 6-1. 여러 직원이 한 DB 를 쓸 때

**한 기기(브라우저) = 한 사람**이 전제다. 설정 → 직원에서 이 기기를 쓰는 사람을 고르면,
그 값이 Notion `직원` Property 로 기록되고 행을 가르는 두 번째 기준이 된다.
직원 필드를 매핑해 놓고 사람을 고르지 않으면 동기화를 **멈춘다** — 누구 것인지 모르는
행을 만들어 서로의 기록을 섞는 것보다 낫다.

선택지는 Notion `직원` Property 의 실제 옵션에서 읽어 온다. 사람이 늘면 Notion 에서
옵션을 추가하고 "스키마 다시 읽기"만 누르면 된다 (앱 배포 불필요).

### 6-2. 한 사람이 기기를 옮겨 다닐 때 — 이벤트 로그

기록은 원래 브라우저 안에만 쌓였다. 그래서 데스크탑에서 출근하고 노트북에서 퇴근하는 것이
불가능했고, 더 나쁘게는 노트북이 같은 날짜의 행을 자기 기준으로 덮어써서 오전 기록을 지웠다.

이제 `이벤트로그`(rich_text) Property 에 **그날의 이벤트 목록 자체**를 실어 둔다
(`shared/dayLog.ts`). 형식은 `v1 U:<수정시각> V:<휴가ms> i:<자정기준 상대ms> …` 이고,
하루치가 수백 바이트라 rich_text 한 조각(2000자)에 넉넉히 들어간다.

- **쓸 때** — 서버가 기존 행의 로그를 읽어 합친 뒤 근무시간을 다시 계산한다.
  조회와 쓰기가 한 요청 안에서 끝나므로, 클라이언트가 "읽고→합치고→쓰는" 동안
  다른 기기가 끼어들어 기록이 사라지는 일이 없다. 그래서 `computeDay` 와 `buildRecord`
  가 `shared/` 에 있다 — 서버도 같은 계산을 해야 하기 때문이다.
- **읽을 때** — 앱을 열 때와 창으로 돌아올 때 `GET /api/notion-day` 로 그날의 로그를
  가져와 합친다. 기기를 옮겨 앉는 순간이 곧 창을 다시 보는 순간이다.
- **합치는 규칙** — 이벤트는 **합집합**이다(append-only 라 지우는 연산이 없다).
  같은 이벤트인지는 (종류, 시각) 으로 판단한다. 중복 출근처럼 의미가 겹치는 것은
  `computeDay` 가 이미 무시하므로 그대로 둬도 계산이 어긋나지 않는다.
  휴가시간처럼 덮어쓰는 값만 `updatedAt` 이 큰 쪽을 택한다.

매핑하지 않으면 이 기능만 꺼지고 나머지는 그대로 동작한다 (기기별 기록).

### 6-3. 퇴근 취소 — `resume` 이벤트

퇴근 버튼을 잘못 눌렀거나 일이 더 생겼을 때를 위해 **업무 복귀하기** 버튼이 있다.
`resume` 이벤트가 붙으면 퇴근이 취소되고 그 시각부터 근무시간이 다시 쌓인다.
퇴근~복귀 사이 구간은 근무시간에도 자리 비움시간에도 넣지 않는다 (`pausedMs` 로만 센다).
집에 갔다가 밤에 다시 앉은 3시간을 "자리 비움"으로 적으면 숫자가 거짓말이 되기 때문이다.

### 7. Secret 은 브라우저에 없다

`NOTION_TOKEN` 은 서버리스 함수에서만 읽힌다. 프론트엔드 번들에 들어가는 값은
`VITE_` 접두사가 붙은 것뿐이며, Notion 관련 값에는 그 접두사를 쓰지 않는다.
(애초에 Notion API 는 CORS 를 허용하지 않아 브라우저 직접 호출이 불가능하다.)

## 로컬 실행

```bash
npm install
cp .env.example .env      # NOTION_TOKEN / NOTION_DATABASE_ID 입력
npm run dev               # http://127.0.0.1:5173
```

개발 서버는 배포와 **동일한 API 라우터**를 미들웨어로 물려서 실행하므로,
로컬에서 통과한 동작이 배포에서도 그대로 동작한다.

```bash
npm test              # 단위/통합 테스트 (모의 Notion 서버 사용)
npm run e2e           # Playwright 종단 테스트 (실제 브라우저 + 가상 시계)
npm run build         # production 타입체크 + 프로덕션 빌드
npm run typecheck     # 테스트·E2E 까지 포함한 전체 타입체크
npm run verify:deploy # 배포 형태(.vercelignore 적용)로 빌드를 재현해 검증
```

### 빌드 설정이 두 벌인 이유

| 파일 | 범위 | 쓰는 곳 |
| --- | --- | --- |
| `tsconfig.json` | 전부 (src·api·shared·tests·e2e·scripts) | 편집기, `npm run typecheck`, vitest |
| `tsconfig.build.json` | production 소스만 (테스트 제외) | `npm run build` → 배포 |
| `vite.config.ts` | production 빌드 | `vite build`, `vite dev` |
| `vitest.config.ts` | 위 설정 + `test` 블록 | `vitest` |

Vercel 은 `.vercelignore` 로 걸러진 파일만 업로드한 뒤 `npm run build` 를 돌린다.
그래서 **production 타입체크가 테스트 파일을 검사하면 안 된다** — 업로드되지 않은
파일(`tests/mocks/notionMock.ts` 등)을 참조하다 `TS2307` 로 배포가 깨진다.
전체 체크아웃 상태인 로컬·CI 에서는 재현되지 않으므로, `npm run verify:deploy` 가
배포 조건을 그대로 복제해 검증하고 CI 에서도 같은 검사를 돌린다.

### `api/` 를 수정할 때 — 상대 import 에 `.js` 를 붙인다

```ts
import { handleApiRequest } from './_router.js';   // ✅
import { handleApiRequest } from './_router';      // ❌ 배포하면 함수가 죽는다
```

`package.json` 이 `"type": "module"` 이므로 서버리스 함수는 **ESM 으로 로드**된다.
Node 의 ESM 로더는 상대 경로에 확장자를 요구하는데, TypeScript 는 작성한 경로를
그대로 내보내므로 확장자가 없으면 컴파일·빌드는 전부 통과하고 **런타임에만**
`ERR_MODULE_NOT_FOUND` 로 죽는다. 배포는 "성공"으로 뜨고 `/api` 만 500
(`FUNCTION_INVOCATION_FAILED`)이 되므로 원인을 찾기 어렵다.

TypeScript 는 `./_router.js` 를 `_router.ts` 로 정상 해석하므로 타입체크에 문제가 없다.
`npm run verify:deploy` 가 함수를 실제로 ESM 으로 로드하고 호출까지 해서 이 부류를 잡는다.

> 불변 조건: `tsconfig.build.json` 의 `include` 대상은 `.vercelignore` 에 들어가면 안 된다.
> 같은 이유로 vitest 의 `test` 블록은 `vite.config.ts` 가 아니라 `vitest.config.ts` 에 둔다.

## 배포

### A. Vercel — Notion 동기화까지 쓰려면 이쪽 (권장)

정적 파일과 `/api/*` 서버리스 함수가 한 번에 배포된다.

1. https://vercel.com/new 에서 이 저장소를 import (프레임워크는 Vite 로 자동 인식)
2. **Environment Variables** 에 추가:

   | Key | Value |
   | --- | --- |
   | `NOTION_TOKEN` | `ntn_...` (아래 "Notion 준비" 참고) |
   | `NOTION_DATABASE_ID` | 근무시간 DB 의 32자리 ID |
   | `NOTION_ALLOW_WRITE` | `1` |
   | `APP_ACCESS_KEY` | (선택) 아무 문자열. 설정하면 앱 설정에 같은 값을 입력해야 동작 |

3. Deploy → `https://<프로젝트>.vercel.app`

### B. GitHub Pages — 서버 없이 바로 쓰는 정적 배포

`.github/workflows/deploy-pages.yml` 이 포함돼 있다.
저장소 **Settings → Pages → Source 를 "GitHub Actions"** 로 한 번만 바꾸면 이후 push 마다 배포된다.

주소: `https://<username>.github.io/<repo>/`

## Notion 준비

1. https://www.notion.so/my-integrations → **New integration** → Internal
   → Secret(`ntn_...`) 복사 → `NOTION_TOKEN`
2. 근무시간 DB 를 전체 페이지로 열고 우측 상단 `···` → **Connections → 방금 만든 integration 추가**
   (이걸 하지 않으면 API 가 DB 를 찾지 못한다)
3. DB URL 에서 ID 를 복사 → `NOTION_DATABASE_ID`

   ```
   https://www.notion.so/<workspace>/<32자리 DATABASE_ID>?v=<viewId>
                                     ^^^^^^^^^^^^^^^^^^^
   ```

4. 배포된 앱 → **설정 → 연결 확인 → 스키마 다시 읽기**
5. **Property 매핑** 에서 실제 Property 를 고른다.
   `날짜` 는 중복 방지 기준이므로 반드시 지정한다. 여러 명이 쓰는 DB 라면 `직원` 도
   반드시 지정한다. 나머지는 필요한 것만 고르면 되고, 고르지 않은 필드는 기록에서
   제외될 뿐 오류가 나지 않는다.
6. **설정 → 직원** 에서 이 기기를 쓰는 사람을 고른다. (기기마다 한 번씩)

### 진단 도구 — `npm run notion:doctor`

토큰·연결·스키마를 터미널에서 한 번에 확인한다. 앱과 **같은** `api/_notion.ts` 코어를
쓰므로 여기서 통과하면 앱에서도 동작한다.

```bash
npm run notion:doctor                   # 스키마 조회 + 매핑 제안 (읽기 전용)
npm run notion:doctor -- --list         # integration 이 접근 가능한 DB 목록 (ID 찾기)
npm run notion:doctor -- --db=<URL|ID>  # .env 대신 직접 지정 (URL 통째로 가능)
npm run notion:doctor -- --write-test   # 실제 저장 + 중복 방지까지 검증
```

- 기본 동작은 **읽기 전용**이다. 아무것도 만들지 않고 아무것도 고치지 않는다.
- `--write-test` 도 대상 날짜에 행이 이미 있으면 **덮어쓰지 않고 중단**한다.
  빈 날짜로 검증하려면 `--date=YYYY-MM-DD` 를 준다.
- 실패 시 원인별 해설을 출력한다 (토큰 오류 / DB 미연결 / ID 형식 오류 등).
  가장 흔한 실수는 2번(Connections 추가)을 빠뜨리는 것이며, 이 경우 API 에는
  DB 가 아예 없는 것처럼 보인다 — `--list` 로 바로 확인된다.
- 마지막에 JSON 요약 블록을 출력한다. 토큰은 포함되지 않으므로 그대로 공유해도 된다.

앱이 다루는 논리 필드: 날짜 · 출근시간 · 퇴근시간 · 실제 근무시간 · 자리 비움시간 ·
휴가시간 · 인정 근무시간 · 상태

## Notion 페이지에 Embed

1. 배포 URL 복사
2. Notion 페이지에서 `/embed` 입력 → **Embed** 선택
3. URL 붙여넣기 → **Embed link**
4. 블록 아래 가장자리를 드래그해 높이를 맞춘다

두 가지 모드가 있다.

| 붙여넣을 URL | 결과 |
| --- | --- |
| `https://<배포주소>/` | 전체 앱 (탭 4개). 높이 **900px 이상** 권장 |
| `https://<배포주소>/?embed=1` | 컴팩트 위젯. 높이 **280px** 정도 |

### 위젯 모드 (`?embed=1`)

임베드 블록은 "URL 하나 = 블록 하나"다. 사람마다 블록을 하나씩 두고 URL 에 그 사람을
적어 두면, 그 위젯은 언제나 그 사람의 기록으로 동작한다.

```
https://<배포주소>/?embed=1&employee=박진규
```

| 파라미터 | 뜻 |
| --- | --- |
| `embed` / `widget` / `view` | 값이 `0/false/no/off/full/app` 이 아니면 위젯 모드 |
| `employee` (또는 `name`) | 이 위젯의 주인. 저장된 값보다 URL 이 우선한다 |
| `key` | 접근 키(`APP_ACCESS_KEY`). 반영한 뒤 주소에서 지운다 |
| `theme` | `light` / `dark`. Notion 테마와 OS 테마가 어긋날 때 |

빈 값(`?employee=`)은 "지정하지 않음"으로 본다 — URL 로 설정을 **지울** 수는 없다.
백엔드 주소는 일부러 파라미터로 받지 않는다. 그것까지 URL 로 바꿀 수 있으면 링크
하나로 접근 키를 남의 서버에 보내게 만들 수 있기 때문이다.

`key` 를 URL 에 넣으면 그 페이지를 볼 수 있는 사람은 블록 주소에서 키를 읽을 수 있다.
팀 전용 페이지가 아니라면 넣지 말고, 위젯 설정 화면에서 한 번 입력하는 편이 낫다.

### 임베드에서 조심할 것

- **iframe 저장소는 "상위 사이트 + iframe 출처"로 나뉜다.** 사람이 다르면 브라우저가
  다르니 기록도 갈린다 — 여기까지는 의도한 대로다. 함정은 **같은 페이지의 위젯 두 개는
  그 둘이 똑같아서 한 칸을 공유한다**는 것이다. 그대로 두면 하정언 위젯과 박진규 위젯이
  서로의 이름과 근무시간을 덮어쓴다(실제로 그랬다). 그래서 URL 에 `employee` 가 있으면
  `worktime.studio.state.v1::<이름>` 으로 칸을 가른다. 칸을 처음 만들 때 공용 칸에서
  **접근 키·매핑·스키마·휴가 정책만** 물려받고, 이름·기록·대기열·pageId 는 비운다.
- **Safari 기본 설정은 iframe 저장소를 아예 막는다.** 앱이 감지해 위젯 상단에 붉은
  경고를 띄우고 **전체 화면 ↗** 로 새 탭에서 쓰도록 안내한다.
- **임베드와 새 탭은 서로 다른 저장소를 쓴다.** 설정은 각각 한 번씩 해야 한다. 근무 기록
  자체는 Notion 을 통해 합쳐지므로(§6-2) 문제가 되지 않는다.
- **주기적 갱신.** 위젯은 노션 페이지에 하루 종일 떠 있어서 focus 이벤트가 거의 발생하지
  않는다. 그래서 위젯 모드에서만 2분마다 Notion 을 읽어 다른 기기 기록을 반영한다.
- **버튼은 사라지지 않는다.** 서버 오류·네트워크 문제는 배너로만 알리고 조작부는 항상
  남긴다. 기록은 로컬에 먼저 쌓이고 나중에 동기화된다.
- **프레임 허용.** `vercel.json` 의 `frame-ancestors` 가 `notion.so` / `notion.site` /
  `notion.com` 을 허용한다. 다른 곳에 임베드하려면 여기에 추가해야 한다.
