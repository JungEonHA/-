# 예시 — 에이전트 계약서의 해상도 기준

아래는 **가상의 예시**다. 우리 회사 사실이 아니라, "이 정도까지 적어야 에이전트가 실제로
움직인다"는 기준을 보여주기 위한 것이다. [`INTAKE.md`](./INTAKE.md) C 블록을 채울 때 참고한다.

---

## 나쁜 예 — 이러면 못 만든다

> **대본 작가 에이전트**
> 숏드라마 대본을 쓴다. 재미있고 몰입감 있게 쓴다. 트렌드를 반영한다.

이 정보로 만들 수 있는 건 "대본 써줘"라고 부탁하는 껍데기뿐이다. 자율적으로 못 돈다 —
언제 시작할지, 어디서 소재를 가져올지, 다 쓰면 어디에 두고 누구에게 넘길지, 뭐가 합격인지
하나도 정해져 있지 않아서 매번 사람에게 물어야 한다.

---

## 좋은 예

### 에이전트: `scriptwriter` (숏드라마 대본)

**1. 목적 한 줄**
승인된 소재 1건을 받아 60초 숏드라마 대본 1편으로 만들고, 스토리보드 에이전트에게 넘긴다.

**2. 입력 — 무엇이 있으면 시작하는가**
Notion `소재 DB` 에 `상태 = 대본대기` 인 행이 생기면 시작한다.
그 행에서 읽는 값: 소재 한 줄, 타깃 IP, 참고 링크, 우선순위.
행이 여러 개면 우선순위 → 생성일 순으로 하나씩. **한 번에 한 편만 잡는다**
(잡는 즉시 `상태 = 대본작업중` 으로 바꿔서 다른 에이전트가 중복으로 안 잡게 한다).

**3. 출력 — 정확히 무엇을, 어디에, 어떤 이름으로**
- 파일: `company/scripts/{IP코드}/{화번호}-{슬러그}.md`
- 형식: 아래 고정 템플릿
  ```
  # {제목}
  훅(0-3초):
  ## 씬 1  [장소 / 시간 / 인물]
  대사:
  지문:
  ...
  엔딩 후킹(다음 화 유도):
  ```
- Notion `대본 DB` 에 행 추가 (제목, IP, 화번호, 파일경로, 예상 러닝타임, 등장인물 목록)
- 원본 소재 행을 `상태 = 대본완료` 로 변경

**4. 완료 기준 (Definition of Done)**
- [ ] 총 대사 분량이 소리 내어 읽어 55~65초 (한국어 기준 초당 4.5자로 환산해 검산)
- [ ] 첫 3초 안에 갈등 또는 질문이 제시된다
- [ ] 씬 수 6개 이하 (영상 생성 비용 상한 때문)
- [ ] 등장인물이 `company/brand/{IP코드}/characters.md` 에 등록된 인물만 나온다
- [ ] 금지 표현 목록(`company/brand/banned.md`)에 걸리는 단어가 없다
- [ ] 마지막 줄이 다음 화를 보게 만드는 형태로 끝난다
- [ ] 실존 인물·실제 상표·실제 사건이 특정되지 않는다

**5. 도구·권한**
- Notion `소재 DB` — 읽기 + 상태 컬럼만 쓰기
- Notion `대본 DB` — 행 추가
- `company/scripts/` — 쓰기
- `company/brand/` — 읽기 전용
- 웹 검색 — 허용 (트렌드 확인용, 하루 20회 이내)
- 영상·이미지 생성 API — **접근 없음** (그건 다음 에이전트 일)

**6. 결정 권한**
- 혼자 결정: 제목, 씬 구성, 대사, 등장인물 배치(등록된 인물 내에서), 톤 조절
- 사람에게 물어봄: 새 등장인물 추가, IP 세계관 설정 변경, 시리즈 아크 방향 전환
- 절대 안 함: 소재 DB 에 없는 소재로 임의 제작, 대본 파일 삭제·덮어쓰기, 직접 업로드

**7. 실패했을 때**
- 완료 기준 중 실패한 항목이 있으면 스스로 **최대 2회** 고쳐 쓴다
- 3회차에도 안 되면 → 소재 행을 `상태 = 보류(대본실패)` 로 바꾸고 실패 사유를 코멘트로 남긴 뒤 **다음 소재로 넘어간다**. 멈추지 않는다
- 같은 IP 에서 연속 3건 실패하면 → 사람 호출 (기준 자체가 잘못됐을 가능성)

**8. 하루 리듬**
매일 09:00 에 깨어나 큐를 확인한다. 큐가 비어 있으면 아무것도 안 하고 종료한다(사람 안 부름).
하루 최대 4편까지. 그 이상은 만들지 않는다.

**9. 지표**
- 대본 → 영상 완성까지 반려 없이 통과한 비율
- 편당 평균 재작성 횟수
- 이 에이전트가 쓴 대본으로 만든 영상의 3초 시청 유지율

## 이 예시에서 눈여겨볼 것

| 포인트 | 왜 중요한가 |
| --- | --- |
| **"한 번에 한 편만 잡고, 잡는 즉시 상태를 바꾼다"** | 에이전트 9명이 동시에 도는 순간 중복 작업이 최대 사고 원인이다. 잠금 규칙이 곧 협업 규칙이다 |
| **완료 기준이 체크리스트다** | "재미있게"는 검증이 안 된다. 체크리스트여야 에이전트가 스스로 채점하고 다시 쓴다 |
| **실패 시 "멈추지 않는다"가 명시됨** | 이게 없으면 한 건 막혔을 때 하루가 통째로 선다 |
| **권한에 "접근 없음"이 적혀 있다** | 할 수 있는 것보다 **못 하게 막은 것**이 자율 운영의 안전장치다 |
| **큐가 비면 사람을 안 부른다** | 할 일 없을 때 사람을 부르는 에이전트는 금방 무시당한다 |
| **지표가 본인 산출물이 아니라 다음 단계 결과다** | 대본 잘 썼는지는 대본이 아니라 영상 성과로 판정된다 |
