# 인테이크 질문지

이 파일을 그대로 채워서 주면 된다. 문장으로 써도 되고, 표를 부수고 메모처럼 던져도 된다.
**모르거나 아직 안 정한 항목은 `?` 로 남겨 둔다.** 빈칸으로 두는 것보다 `?` 가 낫다 —
`?` 는 "여기서 결정이 필요하다"는 신호로 읽고, 빈칸은 놓친 것으로 읽는다.

우선순위: **A · B · E** 가 1차 필수. C 는 3명분만 먼저. D · F · G · H 는 그 다음.

### 각 에이전트마다 — 아래 9개 항목

> 이 9개가 채워지면 에이전트가 실제로 동작한다. 하나라도 비면 그 지점에서 멈추거나 사람을 부른다.

```markdown
#### 에이전트: (이름)

1. 목적 한 줄:
   "무엇을 만들어 누구에게 넘기는가"

2. 입력 — 무엇이 있으면 일을 시작하는가:
   (예: 아이디어 DB 에 status=승인 인 행이 생기면)

3. 출력 — 정확히 무엇을, 어디에, 어떤 이름으로:
   (예: `company/scripts/{IP}/{화번호}.md`, Notion 대본 DB 에 행 추가)

4. 완료 기준 (Definition of Done) — 체크리스트로:
   - [ ]
   - [ ]
   - [ ]

5. 도구·권한 — 쓸 수 있는 API/계정, 읽기전용인지 쓰기까지인지:

6. 결정 권한:
   - 혼자 결정해도 되는 것:
   - 사람에게 물어야 하는 것:
   - 절대 하면 안 되는 것:

7. 실패했을 때:
   (재시도 몇 번 → 그래도 안 되면 넘김/보류/사람 호출 중 무엇)

8. 하루 리듬 — 언제 깨어나는가:
   (예: 매일 09:00 / 앞 단계가 끝나면 / 사람이 부를 때만)

9. 잘하고 있는지 보는 지표:
```

## D. 사람 2명 — 협업 지점

| 항목 | 사람 ① | 사람 ② |
| --- | --- | --- |
| 이름 / 호칭 | | |
| 맡은 영역 | | |
| **반드시 직접 결정해야 하는 것** | | |
| 표본만 보면 되는 것 | | |
| 안 봐도 되는 것 | | |
| 주 근무 시간대 | | |

**자율성의 핵심 규칙** — 이 3개가 "매일 자동으로 돌아간다"의 성패를 가른다.

| 상황 | 어떻게 할까 |
| --- | --- |
| 승인 요청 후 사람이 **12시간** 답 없으면 | 대기 / 보류하고 다음 일 / 기본값으로 진행 — 어느 쪽? |
| 사람이 **주말·휴가**로 자리를 비우면 | 파이프라인 멈춤 / 승인 없는 단계까지만 진행 — 어느 쪽? |
| 에이전트끼리 결과가 충돌하면 (예: 대본과 아트 방향 불일치) | 누가 최종 결정? 사람? 특정 에이전트? |

| 예: `/승인 3` | 3번 대기 건 승인하고 다음 단계 자동 진행 |

## E. 회사의 기억 — 상태를 어디에 쌓는가

에이전트는 어제 한 일을 읽을 곳이 있어야 자율적으로 움직인다. 이 블록이 비면 매일 처음부터 시작한다.

| 항목 | 답 |
| --- | --- |
| 진실의 원본은 어디인가 (Notion / Drive / Git / 섞어서) | |
| Notion 워크스페이스 사용 중인지, 쓰는 DB 이름 전부 | |
| 각 DB 의 속성(컬럼) 구조 — CSV 나 캡처로 주면 가장 좋음 | |
| 영상·이미지 원본 저장소 (Drive / S3 / 로컬 / 기타) + 폴더 규칙 | |
| 파일명 규칙이 있는지 | |
| 지금 매일 어딘가에 기록하고 있는 것이 있는지 | |
| 에이전트가 **쓰기**까지 해도 되는 곳 / 읽기만 해야 하는 곳 | |

> 참고: 이 레포에 이미 Notion 연동(`NOTION_TOKEN`, 근무시간 DB)이 붙어 있다.
> 같은 워크스페이스를 쓸 거면 통합 토큰을 재사용할 수 있는지 알려 달라.
